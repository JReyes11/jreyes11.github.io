Fun with Chrome Extensions

In my previous post, I worked on leveraging AI to generate test cases based on a Github Diff. I wanted to take this a step further, so I built a Chrome Extension to accomplish this process in 3 clicks.

The last time I build a Chrome extension...
A few years ago while working as an SDET at a Healthcare company, I built a chrome extension that was used internally by many of the Quality Engineers and Developers cross-functionally. The tool was built to solve the lengthy cumbersome process of generating internal serial numbers - which were required when testing the purchase and product registration workflows in the lower environments.

The tool allowed this process to be reduced into a 2-click process that would complete in under 15 seconds by leveraging a number of internal API's.

Fast forward to present day...
Building this Chrome extension was different, in the sense that the goal is to leverage AI, via an API to generate test cases based on a Github diff. The value this tool offers is a no-nonsense process in which Quality Engineers can quickly get an idea on areas of focus when testing changes in a pull request.

Challenges
There is limited real estate when working with chrome extensions, so the design must be thoughtful and intuitive. As much as I secretly wish I were a UI Designer, I initially struggled with the layout. How can I fit the following...

  • Allow the user to select from a collection of repositories.
concept of how the test case results should be rendered. I came to the conclusion that once the test cases were generated, I should allow the user to download them locally.

Next I had to decide the format in which to save the test case results returned by Gemini AI. I want this to be a tool that users rely on, so I decided to save the results in an HTML document that contains a table and a search field that could be used to filter the test cases. This led me down the road of using "DataTables", which made this process almost effortless.
